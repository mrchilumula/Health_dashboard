# Implementation Plan: Galaxy Watch 9 to Health Connect Cloud Bridge (HealthSync Gateway)
Build an Android phone application (`HealthSync Gateway`) that reads health data synchronized from a Samsung Galaxy Watch 9 via Android Health Connect, maps valid readings to the Health Digital Twin REST API contract (`POST /api/health-records`), manages a local Room outbox for reliable background/offline synchronization with WorkManager, and displays sync status, data previews, permission state, and settings using Jetpack Compose (Material 3).
## User Review Required
> [!IMPORTANT]
> **Cloud Contract Field Completeness Rule**: The backend endpoint `POST /api/health-records` requires all 6 parameters (`steps`, `calories`, `distance`, `spo2`, `temperature`, `syncCount`). Per requirements, we **NEVER** substitute zero or fake values if a permission is denied or a reading is missing. When any required metric is missing, the bridge holds the record in Room as `MISSING_REQUIRED_FIELDS` and displays an explicit status in the UI to notify the user.
> [!NOTE]
> **Network Security Configuration**: Local HTTP testing (e.g. `http://192.168.1.25:8080`) is supported via a custom `res/xml/network_security_config.xml` permitting cleartext HTTP only for local IP ranges, while enforcing HTTPS for all production URLs.

  1. Health Connect data reading & mapping.
  2. Outbox persistence in Room.
  3. Field validation (ensuring all 6 required fields are present).
  4. Uploading pending records to cloud API.
  5. Monotonic counter increment (`syncCount`) upon success.
  6. Cursor update.
  7. Thread-safe execution using Mutex to prevent manual & WorkManager sync overlap.

## Verification Plan
### Automated Tests
1. **Unit Tests (`app/src/test/java/...`)**:
   - `HealthConnectDataMapperTest`: Test conversion of meters, active calories (not total), SpO2 percentage, temperature (°C), missing field handling (ensuring zero is NEVER fabricated).
   - `StableEventIdTest`: Test stable ID generation (`userId + sourceRecordId + recordType + startTime + endTime`).
   - `OutboxEntityValidationTest`: Test that incomplete records transition to `MISSING_REQUIRED_FIELDS` state without uploading.
   - `HealthSyncRepositoryTest`: Test manual sync flow, successful POST handling, HTTP 400/409/5xx response handling, and monotonic `syncCount` increment logic.
2. **Instrumentation Tests (`app/src/androidTest/java/...`)**:
   - `OutboxDaoTest`: Test Room database CRUD operations, pending count queries, and outbox state transitions using `inMemoryDatabaseBuilder`.
   - `SyncWorkerTest`: Test WorkManager execution and retry rules.
### Manual Verification
1. Build and assemble project using `./gradlew assembleDebug`.
2. Launch application on test device or emulator.
3. Test settings modification (changing Base URL to local dev IP).
4. Verify onboarding flow, permission request handling, dashboard state updates, data preview tags, and manual sync execution.
